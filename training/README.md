# Training and evaluating a Ken model

Fine-tunes **Gemma 4 12B** (`unsloth/gemma-4-12b-it`) with 4-bit QLoRA, using [Unsloth](https://github.com/unslothai/unsloth),
so that it writes Ken without any reasoning. Everything here is reproducible from this repository.

| File | Purpose |
|---|---|
| `tables.py` | The four tables the examples are about, with their descriptions; writes `tables/*.csv` |
| `gen_data.py` | Builds `data/{train,val,test,test_unseen_table}.jsonl`: English task → Ken program, every program executed and checked against pandas |
| `train.py` | QLoRA fine-tuning (loss on the answer only) |
| `evaluate.py` | Scores a base model or an adapter on the benchmark tasks and on the held-out generated tasks |
| `data/` | The generated data (committed, ~3 MB) |
| `tables/` | `bookings.csv`, `shipments.csv`, `grades.csv`, generated by `tables.py` (`orders.csv` is in `examples/data`) |
| `out/` | Adapter, training log and evaluation results (git-ignored) |

## What the model is taught

The prompt is `kenlang.llm.build_prompt(task, data_description)`: the language reference
([`src/kenlang/reference.md`](../src/kenlang/reference.md)), a description of the table the task is about, and
the task. The answer is the program followed by the end-of-turn token. The chat template is Gemma 4's, with
reasoning **off**, which is also how the model is evaluated.

### Data design

**Tables.** A model that sees a single table cannot tell the language from the data. The data therefore uses
three tables with different column names, values and sizes of numbers — `orders`, `bookings` (hotel stays) and
`shipments` — and each prompt carries the description of its own table. A fourth table, `grades`, has a different
shape (no price column) and is **never** used for training: `test_unseen_table.jsonl` (60 examples) measures how
the model copes with a table it has not seen.

**Pieces.** `gen_data.py` composes tasks from pieces — a measure (count, sum, revenue, average, maximum, distinct
counts, …), a grouping (a category, the state, the month), 0–2 filters (`eq`, `ne`, `in`, `ge`, `gt`, `le`, `lt`,
`has`, …) and an output shape (sorted by key, top *n*, bottom *n*, all by value, threshold) — plus scalar
questions, distinct lists and "write a CSV" tasks. About 30 % are two-part programs. The tasks are worded in
several ways.

**Harder constructs.** About 40 % of the examples use `if` inside a block, `def`, or `as` inside a block:

| Piece | Shows |
|---|---|
| percentage of a group that meets a condition | `as` inside the block, `div`, `mul 100` |
| ratio of two measures per group | two values kept with `as` inside the block |
| share of a total | a total stored with `as` and used inside the block |
| classes by a value, counted with `freq` | `if` (nested), inline or in a `def` |
| labels for group results | `if` after `by`, inline or in a `def` |
| a value scaled with a word of your own | `def` with `mul`/`round` |

The benchmark's skills are all taught, but none of its tasks or answers is in the data. Generalisation is
measured on the generated test sets and, above all, on the table the model never saw.

Safeguards, all enforced by `tests/test_training_data.py`:

- every program is **run**, and its output must equal a result computed independently with pandas;
- one program per task text, and the splits are made on the task text, so train/val/test share no task;
- examples whose output equals a benchmark answer are dropped;
- the held-out table never appears in `train`, `val` or `test`;
- the committed table files are exactly what `tables.py` produces, and each description matches its file;
- a variable or word of your own is never named like a command (`as sub` once made a program unparsable).

## Reproduce

Use a CUDA GPU with ≥ 20 GB. Unsloth pins `transformers<=5.5.0`, which cannot read Gemma 4's
`gemma4_unified` architecture, so install in two steps:

```
python -m venv .venv-train && . .venv-train/bin/activate     # Windows: .venv-train\Scripts\activate
pip install -r training/requirements.txt
pip install "transformers==5.17.0"                            # overrides unsloth's pin
pip install -e .                                              # the kenlang package itself

python -m training.tables                                     # optional: the tables are committed
python -m training.gen_data 2000                              # optional: data is committed
python -m training.train --max-steps 5                        # smoke test
python -m training.train                                      # ~100 minutes on an RTX 5090 Laptop
python -m training.evaluate --adapter none --n 3 --tag base
python -m training.evaluate --adapter training/out/adapter --n 3 --tag finetuned
```

Hyper-parameters (`train.py`): LoRA rank 16 / alpha 16 on all attention and MLP projections of the language
model, learning rate 2e-4 with linear decay, effective batch 8, one epoch over 2,025 examples
(253 steps), `adamw_8bit`, bf16, maximum sequence length 3,072 (the longest example has 2,038 tokens).

The model is evaluated with temperature 0.6, top-p 0.95, top-k 64, three attempts per task, on three sets:
the seven benchmark tasks (`bench`), held-out generated tasks about the training tables (`gen`) and generated
tasks about the table it never saw (`unseen`). Programs run in a separate process in an otherwise empty
directory that contains only the table the task is about.

## Notes on the environment

- `unsloth` creates an `unsloth_compiled_cache/` directory in the working directory; it is git-ignored.
- On Windows, the first training step compiles kernels and is slow.
- `python -m training.train --dry` prints one fully rendered training example without touching the GPU.
